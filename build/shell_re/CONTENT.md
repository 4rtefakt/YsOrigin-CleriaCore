# Mod content (phase 2a): the save sidecar, the event bus, the grant filter, content/*.ini

The second step of the mod system (MODS.md §7, §12 items 2-7): mods that ADD and CHANGE game content,
and the hooks the randomizer / Archipelago integration stands on. None of this is retail; it is
CleriaCore's own layer, like the F1 shell. Tags: **[CODE]** read in CleriaCore's code, **[DATA]**
checked on the files, **[H]** a choice of this design.

| piece | where | test |
|---|---|---|
| INI reader for data files | `src/cleria/inidoc.{hpp,cpp}` | `cleria-contenttest` |
| save sidecar `yso_NN.cleria` | `src/cleria/sidecar.{hpp,cpp}` | `cleria-savetest` (2 checks) |
| event bus + per-tick flag diff | `src/cleria/mod_events.{hpp,cpp}` | `cleria-contenttest` |
| grant filter in the VM | `src/cleria/xso.{hpp,cpp}` (`GrantQuery` / `GrantDecision` / `XsoVm::grant_filter`) | `cleria-contenttest` (real `S_1001/S_BOX01.XSO`) |
| content parsers, merge, apply | `src/cleria/content.{hpp,cpp}` | `cleria-contenttest` (20 checks) |
| item table patch hook | `src/cleria/items.{hpp,cpp}` (`set_item_patch`) | `cleria-contenttest` (real INVINFO) |
| live-game glue + F1 **Mods > Content additions** (once its own "Content" tab) | `apps/cleria-view/view_content.inl` + one-line hooks in `view_game.inl` | `drive_regress` `content_chest` / `content_off` / `content_rule` / `shell_subpages` |

`mods::kApiVersion` is now **2**: a mod that declares `ApiVersion=1` keeps working (files/ only),
and its `content/` folder is ignored with a note; a mod without `ApiVersion` is current (2).

## 1. Faithfulness

With no content mod active (no mods, `UseMods=0`, or only reskin mods):
- the grant filter is installed but every query is `Pass` (it only emits events), no item patch is
  set, no pickup is placed, text is untouched, no sidecar file is written or read into state;
- proven: `tools/goldens.py compare` 7/7; `tools/drive_regress.py` 9/9 (the 6 existing cases
  unchanged); a `CLERIA_DRIVE` run of the S_1001 chest (barrier break, chest open, treasure box)
  gives byte-identical frames (3 shots, md5) from the pre-change exe, the new exe with no mods, and
  the new exe with `chest_swap` installed but turned off;
- `cleria-contenttest`: a pass-through filter on the real `S_BOX01.XSO` reproduces the unfiltered
  run grant for grant, flag for flag.

## 2. The save sidecar (`yso_NN.cleria`)

The retail record (save.hpp) is a fixed 0x1FC8-byte image of the game-state block that the real
exe must keep accepting, so nothing CleriaCore adds can live in it. Beside each `yso_NN.bin`:

```ini
; CleriaCore save sidecar (build/shell_re/CONTENT.md). The .bin beside it is the retail save.
[cleria]
Version=1
Mods="sample.chest_swap 1.0.0"      ; the content mods active at the save (a stamp, informative)
[flags]                             ; CleriaCore flags by name: rule Once state, pickups collected, mod flags
chest_swap.lantern=1
rule.lantern_found=1
[items]                             ; new-item counts (ids 0x100..0x1FF; no g_flags cell)
0x100=1
[mod.sample.hello]                  ; a Lua mod's cleria.save storage (LUA_API.md §6): JSON values, %-escaped
rooms="3"
```

- An old sidecar's `[ap]` block (the removed built-in Archipelago client's, AP_GAME.md) is read and ignored,
  and dropped at the next save; the Archipelago Lua mod keeps its state in `[mod.ysorigin.archipelago]`.
- **Written** by `do_save` right after the retail file (`content_save`), **read** by the title's Load
  (`content_title_load`, applied at session start) and the book's Load (`content_load`, before the
  record is applied so the room's pickups are gated by the loaded state), **removed** with the
  slot (book Delete). A new game starts empty.
- [H] **Empty = no file**, and writing an empty sidecar deletes a stale one: an unmodded save writes
  exactly what it wrote before. A sidecar with an unknown / newer `Version`, or foreign text, reads
  as empty. Loading a save whose stamp differs from the active content mods logs a note (no refusal).
- Counts follow the retail inventory rule: `max(count, 0) + n`, capped at 99 (inv_sanitize).
- [not modelled] the game over's Retry restores the continue snapshot, not the sidecar (retail's
  Retry does not reload the save either).

## 3. The event bus (`mod_events.hpp`)

`events::bus()` — subscribe to everything or to one `Kind`; handlers run on the game thread and may
emit in turn (depth 8, deeper emits are dropped and counted).

| kind | emitted at | fields |
|---|---|---|
| `RoomEnter` | end of `spawn_enemies` (the boot room, every door / script warp / load) | `room`, `prev_room` |
| `FlagChanged` | `content_tick`, once per fixed tick after the scripts' grants reached `game.g_flags` | `index`, `old_value`, `new_value` |
| `ChestOpened` | the grant filter: a store that sets the running chest's `Interactable::opened_flag` from 0 | `room`, `script`, `object`, `index` |
| `ItemObtained` | the grant filter (a count cell rising), a chest redirect, a pickup taken, a rule, `content_give` | `item`, `count`, `source` (`chest`, `script`, `pickup`, `rule`, `drive`, `ap`...) |
| `PlayerDeath` | the `[death] HP 0` site | `room` |
| `NewGame` / `Load` | session start / a Load (queued, emitted at the next tick) | `character` / `slot` |
| `Save` | after `do_save` wrote the record and the sidecar | `slot` |

`FlagWatch` re-primes silently after a load / new game, so a wholesale state change is not reported
as 512 changes. The speedrun watcher's own flag diff can move onto `FlagChanged` when merged.

## 4. The grant filter (`XsoVm::grant_filter`)

The CleriaCore twin of the retail Archipelago mod's VM splices (`YsOrigin-Archipelago/mod/src/hook_vm.cpp`:
the grant store 0x567D17 / the `+=` store 0x567DB3, the get-item effect 0x573210, the treasure box
0x574410). Where retail needed four code splices and a 1.5-s "pending box" timer, CleriaCore's VM
calls one function with the full context:

```cpp
struct GrantQuery {   // xso.hpp
    enum class Kind { Store, Icon, Window } kind;
    int sub;                 // 0x64 set, 0x67 add, ... | 0x116 Effect_GetItem | 0xD5 Window_Treasure
    int index;               // Store: the g_flags cell; Icon / Window: the item id
    std::int32_t old_value, value;   // Store: before / after the op
    std::string text;        // Window: the box text
    const std::int32_t* flags;       // the VM's g_flags
    std::string script, object;      // the instance ("s_box01") and its $S0 ("box_01")
    int owner;
};
struct GrantDecision { enum class Action { Pass, Suppress, Replace } action; int index; std::int32_t value; std::string text; };
```

- **Store**: every write of the store family 0x64..0x77 to a g_flags cell (a superset of the
  retail mod's 0x64 / 0x67), after the op computed `value`. Pass keeps it; Suppress restores the
  cell and records no grant; Replace writes `value` to cell `index` instead (an index outside
  0..0x1FF writes nothing: the filter granted it elsewhere, e.g. a new item in the sidecar).
- **Icon** (0x116): Replace shows item `index` rising out of the chest; Suppress shows nothing.
- **Window** (0xD5): Replace shows item `index` (0xFF = no icon) and `text`. [H] `content` never
  suppresses the window: the script's following Wait_Prompt would wait on a box that is not there.
- The chest is known exactly: `ScriptManager::tick_inst` sets `XsoVm::script_name` to the instance
  name; the room is the current one; the key is `<ROOM>/<SCRIPT>` as in the apworld's
  `chests.json` (`S_1001/S_BOX01`). `S_BOX01`'s order [DATA]: 0x116 icon (t0) -> 60 ticks -> the
  grant (`flag89 == -1 ? set 1 : add 1`) -> the box flag 302 -> 0xD5 the box. Unlike retail, the
  icon is re-labelled too, since the chest identity is known before the grant.

## 5. content/*.ini

A mod's `content/` folder; a file is picked by its name's prefix (`items*.ini`, `chests*.ini`,
`pickups*.ini`, `rules*.ini`, `text*.ini`), files in name order, mods in load order. A later mod wins
an entry (an item FIELD, a chest key, a pickup id, a rule name, a text key) another also sets; both
get a note in the Mods tab ("content: chest S_1001/S_BOX01 replaced by b.mod" / "replaces ... of
a.mod"). Errors skip the entry and are listed on the mod ("content error: chests.ini line 3: ...").
The INI dialect is cleria.ini's, plus quoted keys, and a trailing comment only after whitespace
(`Icon=X   ; note`; a `;` glued to a word is data, so `Do=give 0x59; text "x"` works).

```ini
; items.ini — retail ids 0x00..0x7F (patch) and NEW ids 0x100..0x1FF [H] (0x80..0xFF refused)
[item.0x59]
Name="Greater Panacea"
Description="Line one.\nLine two."      ; "\n" -> INVINFO's CR/LF
Icon=MY_PANACEA                         ; MENU/ICON/MY_PANACEA.DDS + ICON2/MY_PANACEAV.DDS (from files/)
Magnitude=12
[item.0x100]
Name="Lantern of Solace"
Icon=CS_LANTERN
Kind=flag                               ; key (default: held) | heal (Amount HP, not kept) | gold (Amount SP, not kept) | flag
SetsFlag=chest_swap.lantern             ; Kind=flag: a CleriaCore flag name, or a g_flags index "0x1F0"
```

```ini
; chests.ini — <room>/<script> or <room>/<script>/<item> (only that item's grant, e.g. S_BOX03's per-character items)
[S_1001/S_BOX01]
Item=0x100        ; or none: the chest is empty ("The chest was empty.", no icon)
Count=1
Text="..."        ; optional box text; default: the original re-labelled (name + " x N")
```

```ini
; pickups.ini — placed at room entry, collected once per save (the sidecar flag)
[pickup.chest_swap.fruit]
Room=S_1009
Pos=1.6,2.25,6.4
Item=0x57
Count=1
Flag=chest_swap.fruit     ; default "pickup.<id>"
```

```ini
; rules.ini
[rule.after_boss1]
On=flag 0x1A0 >= 1        ; the comparison turning true | room_enter S_1100 | item 0x63 | chest S_1001/S_BOX01 | death | new_game | load | save
Do=give 0x59 2; text "The tower trembles."; flag 0x1F1 = 1; cflag my.flag += 1
Once=1                    ; once per save (sidecar flag "rule.<name>")
```

```ini
; text.ini — by pool index or by the exact original string; [*] = every script
[MAP/S_10/S_1009/SAVE.XSO]
3="<color:0xffacdae8>New text.\nSecond line."     ; the game's own "\n" escape, kept verbatim
"eft_clear"="eft_clear"
```

### How each applies [CODE]
- **Items**: `set_item_patch` makes every `ItemTable::load` (every load site in cleria-view) run
  `content::patch_items`; the table grows to the highest new id (the ids between stay empty
  records). Icons resolve through `ItemTable::icon_path` -> `load_dds` -> `vfs::resolve`, so a mod's
  `files/MENU/ICON/<STEM>.DDS` is found; the treasure box, the chest icon and the pickup billboard
  draw new items with no further change. **New items are owned in the sidecar**, never in g_flags
  (cells 0x100..0x1FF are story flags).
- **Chests**: `content::decide` on the grant filter (§4). A redirect to a retail item writes that
  item's cell with the inventory rule (in the VM, recorded as a grant, so `apply_script_grants`
  carries it); a redirect to a new item suppresses the cell and `content_give` adds it to the sidecar.
  The box text is re-labelled by `content::treasure_text` (the coloured name span and the ` x N`).
- **Pickups**: built at room entry WITHOUT the spawner's RNG draws ([H] resting, flags 4|8|0x10), so
  a mod pickup does not shift the room's random stream; `Pickup::content` tags them; the touch takes
  new ids through `content_touch_new` (no g_flags write) and marks the collected flag
  (`content_taken`). [not modelled] their floor shadow (no ground probe at placement).
- **Rules**: one bus subscriber; `content::rule_fires` (flag rules fire on the comparison's rising
  edge) + `content::run_rule`. Rule text is shown by the `Shell::hud` layer "content" (a notice card,
  5 s [H]).
- **Text**: `content_script(path)` replaces the four live script loads (the StartScript loader x2, the
  room root, the debug cutscene) and applies `content::patch_script` by the script's virtual name.

### Not done (phase 2a scope notes)
- [not modelled] an Item-page row for new items (MODS.md §7.3.2): the pause book's grids are fixed
  retail tables; the F1 **Content** tab lists the held mod items instead.
- [not modelled] spawning new chests (new SOB objects with an action script); a mod can ship a
  modified room SOB through the vfs today. Pickups are the data-driven way to add items to a room.
- [not modelled] `Kind=buff`, using new items, equipping new gear (the equip aggregator is hardcoded).
- [not modelled] INVINFO text is per language in retail (data_us); the patch applies to the loaded table.
- The title-Load sidecar path is exercised by code review only (drive runs skip the title); the
  book-Load path is covered by `content_chest`.

## 6. For the Archipelago game wiring (phase 2b)

> **History.** This table guided the built-in C++ client (`view_archipelago.inl`, AP_GAME.md), since removed: the
> Archipelago client is now the Lua mod `samples/mods/archipelago_lua`, which reaches the same hooks through the
> generic `cleria.*` API (LUA_API.md: `cleria.events`, `cleria.content.add_filter` / `give`, `cleria.save`,
> `cleria.game.chests`, `cleria.game.frozen`, `cleria.player.set_hp`, `cleria.hud.layer`). `g_content.sc.ap` no
> longer exists (a mod's per-save state is `g_content.sc.mod[<id>]`).

Everything lives in the cleria-view translation unit (`view_content.inl`, static functions), or in
`src/cleria` for testable logic. A `view_archipelago.inl` included after `view_content.inl` could call:

| need | call |
|---|---|
| detect checks | `events::bus().subscribe(events::Kind::ChestOpened, ...)` (room/script = the `chests.json` id), `Kind::FlagChanged` (boss / statue / event flags of `locations.json`), `Kind::RoomEnter` (scene-detected locations) |
| suppress vanilla / show the AP item | `content_add_filter([](const GrantQuery& q, const std::string& room) -> GrantDecision {...})`: Suppress the Store of a randomized chest's item cell, Replace the Icon (an AP icon item id) and the Window (`content::treasure_text(q.text, "Sent X to Y", 1)` or a full text). Runs before chests.ini. |
| grant received items | `content_give(id, count, "ap")` (retail ids by the inventory rule, gold -> SP, new ids into the sidecar; emits `ItemObtained`) |
| persist AP state | (then) `g_content.sc.ap["seed"] = ...`; now `g_content.sc.mod[<id>]` (saved / loaded / cleared with the slot); `g_content.sc.set_flag(...)` |
| the current room / its chests | `g_content.room`, `g_content.chests` (script -> {box flag, object}) |
| freeze-safe receipt | queue while `csMgr.world_frozen()` (the bind block in `view_game.inl` has `csMgr` in scope) |
| a foreign-item icon | a new item id (e.g. `[item.0x1FF] Icon=AP_ITEM`) in a built-in content set, or a reskinned retail icon |
| DeathLink | `Kind::PlayerDeath`; set `player.hp = 0` from the bind block |
| a shell overlay | `shell.hud["ap.status"] = ...` like `content_hud` |

`drive_regress` drives content cases with a scratch settings folder (`mods=[...]`, `content={file: text}`
for a generated test mod, `mods_off`, `absent=[...]`): reuse it for AP cases.
